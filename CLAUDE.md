# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-page static dashboard (Thai UI) tracking the Rubber Authority of Thailand (กยท.) FY2569 action plan. Everything — HTML, CSS, JS — lives in one file, `index.html`. No build, no package manager, no tests; libraries come from cdnjs (only Chart.js loads upfront; SheetJS is loaded via `loadScriptOnce()` when the Excel button is clicked; ExcelJS, html2canvas, jsPDF are lazy-loaded via the `LIBS` map when a report is generated). Viewers open it from a monthly LINE alert, mostly in LINE's in-app browser on phones, so first-load speed matters — don't add blocking scripts to `<head>`.

The user's constraint: nothing may be installed — keep it a plain static file deployable on Vercel, and talk to Supabase with plain `fetch` against the REST API (no supabase-js, no npm).

## Data flow

```
Google Sheet "Data ACP69" --(Apps Script, on menu click)--> Supabase public.sheet_snapshots <--(anon key, read-only)-- index.html
```

- Staff edit the Google Sheet. The bound Apps Script (local file `AppScript`, pasted into the Sheet's script editor by the user) pushes every sheet in `SYNC_SHEETS` to Supabase when the user runs **📁 เมนูระบบ > บันทึกผลการดำเนินงานย้อนหลัง** (`runArchiveProcess` calls `syncToSupabaseLogged` at the end) or **ส่งข้อมูลขึ้นเว็บ (Supabase) เดี๋ยวนี้**. Results are appended to the `ประวัติการบันทึก` sheet.
- `supabase/schema.sql` defines the single table: one row per sheet, `headers` (ordered array) + `rows` (array of arrays of display strings, i.e. what `getDisplayValues()` returns — same as the old gviz CSV export). All sheets are sent in one upsert, so the dashboard never sees a half-updated set. RLS: `select` for anon/authenticated only; writes need the service_role / `sb_secret_` key, stored only in the Apps Script's Script Properties (`SUPABASE_SECRET_KEY`).
- Don't store emails or other personal data in `sheet_snapshots` — the anon key is public, so anyone can read the table.
- Visitor stats: an inline script at the top of `<head>` (which also defines `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `requestSnapshots()` and starts `earlySnapshotsRequest` so data downloads in parallel with Chart.js/fonts) calls `rpc/log_page_view` after `load`. The function is `security definer`; anon has no direct access to `page_views`, and the `page_view_monthly` / `page_view_daily` views are `security_invoker`, so stats are visible only inside Supabase. Only a random per-device id (localStorage `acp-visitor`), source (`?src=` or LINE user agent) and an is-mobile flag are stored.
- LINE OA (menu 🚨 in `AppScript`, broadcast to every follower, so each send uses quota): `sendAlertNow` sends one carousel built by `buildMonthlyMessage`. It has a summary card (`buildSummaryBubble`: project count, budget, disbursement, mean plan % with blanks counted as 0, completed projects, count per status level) and the Early Warning card (`buildRiskBubble`); the risk card is left out when no project is at risk. `getRiskProjects()` computes both with the dashboard's rules: FY2569 status = the status on the row that supplies the plan % (fallback: worst row), and Trigger Point for FY ≥ 2570. Its counts must match the dashboard's (verified Nov 2026: 81/19/5/16). `sendYearEndNow` sends a year-end card from the `ผลสิ้นปีงบประมาณ` sheet (`getYearEndSummary`). Per a user decision (Nov 2026), `yearEndSendBlock(fy)` allows sending only from FY `YE_LINE_FROM_FY` = 2570, and only from `YE_LINE_DAY` = 15 Oct after that fiscal year ends on 30 Sep; the preview still shows the card. `previewLineCards` shows the JSON for LINE Flex Message Simulator without sending. Card buttons open `DASHBOARD_URL?src=line` and `…#lineorg`. Followers are both executives and unit staff, so cards stay organisation-wide (no per-unit broadcasts).
- `indexAppScript` is a separate Apps Script HTML page (Early Warning / LINE alerts), not part of the Vercel site. `AppScript` also references dialog files (`ArchiveDialog`, `CancelDialog`) that exist only in the Apps Script project.

## Source of truth: `Note`

The user edits the dashboard in the local file `Note` (git-ignored). `index.html` is a straight copy of it: when `Note` changes, `cp Note index.html`, then commit and push. Make dashboard edits in `Note` and copy; don't let the two diverge.

## Run / deploy

- Preview: open `index.html` in a browser. It needs network access to Supabase and cdnjs.
- Deploy: Vercel, Framework Preset **Other**, empty build command and output directory; pushing to `main` redeploys. `vercel.json` only sets headers (`X-Robots-Tag: noindex, nofollow`, `nosniff`, `no-referrer`) and `cleanUrls`. If a CSP is ever added, it must allow cdnjs, Google Fonts and `*.supabase.co`.
- No Node/Python on this machine. To smoke-test JS, run headless Chrome (`chrome.exe --headless=new --dump-dom file:///…`) and read the console via `--enable-logging=stderr`.

## Architecture of `index.html`

Several `<script>` blocks, in order:
1. View switching (`activateView`) for the left nav. Each view has a hash link (`#strategy`, `#kpi`, `#annual`, `#masterplan`, `#lineorg`, `#dgarea`; the main page has none) that `activateView` writes with `history.replaceState` and `activateViewFromHash()` reads on load and on `hashchange`. `#method` opens `#methodModal` after `loadAndRender()` finishes (`window.__openMethodOnLoad`). LINE rich-menu buttons and the LINE cards use these links, so don't rename view ids. The views: `view-dashboard`, `view-strategy` (menu "ผลการดำเนินงานตามยุทธศาสตร์", renamed from ความเชื่อมโยงยุทธศาสตร์ Nov 2026; see below), `view-kpi` (ผลการดำเนินงานตามตัวชี้วัดที่สำคัญ, see below), `view-annual`, `view-masterplan`, `view-lineorg` (menu "ความก้าวหน้าแผนปฏิบัติการตามสายงาน", renamed Nov 2026: executive cards `#dgAreaCards` + per-project table `#dgDrilldownPanel`), `view-dgarea` (PA/MOU lists only). Both of the last two are filled by `renderDgAreaView()` via element ids, so moving markup between sections needs no JS change. In `view-lineorg`, `renderDgDrilldown()` shows unit buttons (`#dgUnitChips`) for the selected line, from the global `lineUnits(label, projects)`: units from the `ส่วนงานภายใต้ผู้บริหาร` sheet (`window.ACP_EXEC_UNITS[label]`, built in the loader) plus any project `owner` not listed there, sorted by project count desc (ties keep sheet order). Units with no projects show as disabled dashed buttons. Matching uses `normOwner()`. Report topics mirror the menu (numbered 1–6 in menu order), preceded by the unnumbered `exec` ("สรุปผู้บริหาร", always one A4 page: a single html block so paginate never splits it, plus Excel sheet `สรุปผู้บริหาร`; keep it under the page body height, about 649px, when adding content): `strategy` ("2. ผลการดำเนินงานตามยุทธศาสตร์"; Excel sheet `ยุทธศาสตร์-KPI`), `lineorg` ("5. ความก้าวหน้าแผนปฏิบัติการตามสายงาน": line summary, per-line unit summary from `R.byDg[i].units` (also built with `lineUnits`), one project table per unit; Excel sheet `สายงาน`) and `dgarea` ("6. ความก้าวหน้า PA และ MOU"; Excel sheet `PA-MOU`).
2. Report generator IIFE (PDF/Excel, A4 landscape): picks fiscal year + month from current data or the history sheet; topics in `TOPICS`.
3. `window.ACPDash` — rendering module; `ACPDash.start({records, strategies, orgKpis, historyPeriods, masterPlans})` draws everything.
4. Loader (last block): `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SHEET_SPECS`, then `loadAndRender()` → `fetchSheetBySpec()` per sheet → `buildDashboardData()` / `buildOrgKpis()` / `buildHistoryDataset()` → `ACPDash.start()`. Errors show `#errorOverlay`.

Loader behaviours worth knowing:
- `loadSnapshots()` fetches all rows of `sheet_snapshots` once. `fetchSheetRows(name)` rebuilds `{header: value}` objects plus `__fields` (column order), the same shape Papa.parse used to produce, so the `build*` functions are unchanged. Column order matters: the `ส่วนงานภายใต้ผู้บริหาร` matrix uses `__fields[0]` as the owner column and the rest as executives.
- In `ส่วนงานภายใต้ผู้บริหาร`, only headers matching `ผวก|ผู้ว่าการ` are executive columns (`execCols`). The columns `ตามคำสั่งการยางแห่งประเทศไทย ที่` / `เรื่อง` / `ลงวันที่` (found by `คำสั่ง` / `^เรื่อง` / `ลงวันที่`) become `window.ACP_EXEC_ORDERS`. Orders change often, so the sheet keeps every order with a checkbox column (header `ใช้อยู่`/`ปัจจุบัน`/`ยึด`/`มีผล`, or no header) marking the one in force: only checked orders are shown; if none is checked, every filled order is shown, shown as the หมายเหตุ `#dgOrderNote` under `#dgAreaCards` (user request, Nov 2026). An optional `ปีงบ` column (any column except A) splits the mapping and orders per fiscal year into `window.ACP_EXEC_BY_FY` (blank year = fallback); `execFor(fy)` picks that year, else the latest year ≤ fy, else the blank-year rows. Live records use `execFor(LIVE_FISCAL_YEAR)`; `projectsForPeriod()` maps history owners with `execFor(per.fiscalYear)`, and the header period switch (`show()`) and report `prepare()` swap `ACP_EXEC_UNITS`/`ACP_EXEC_ORDERS` to that year, so past years keep their old line structure when a new order arrives (user request, Nov 2026). From FY2570 the `โครงการ` Owner holds "division/department" (e.g. `ฝสผ./กยท.ข.`), so owners are resolved with `ownerUnitKey(owner, known)`: exact match, else the first "/"-separated part that equals or starts with a unit in the sheet (lead unit = first listed); used for the line mapping and `lineUnits()` grouping.
- `fetchHistorySheetRaw()` returns raw arrays (no header row); `buildHistoryDataset()` reads `ผลการดำเนินงานย้อนหลัง` by column position A–T (layout written by the Apps Script archive; N–P are ARRAYFORMULA columns in the sheet).
- Each `SHEET_SPECS` entry lists alternate sheet names and `required` headers; a missing sheet yields an empty array and is skipped if `optional`. Keep sheet names in sync with `SYNC_SHEETS` in `AppScript`.
- Only the latest `Fiscal_Year` found in the projects sheet is kept.
- KPI results (`view-kpi`, hash `#kpi`, report topic `kpi` "7. ผลการดำเนินงานตามตัวชี้วัดที่สำคัญ", Excel sheet `ตัวชี้วัด`; added Nov 2026): sheet `ผลตัวชี้วัดที่สำคัญ` (in `SYNC_SHEETS`, `SHEET_SPECS.kpiResult`, all fiscal years kept) → `buildKpiResults()` → `window.ACP_KPI_RESULTS` (one record per KPI per `ปีงบ` per round. The sheet has one row per KPI per year with per-round columns (user layout Nov 2026): headers containing `ไตรมาส N` (e.g. `คาดการณ์ไตรมาส1`, `ผลการดำเนินงานไตรมาส 3`) or `สิ้นปี`; un-numbered `หมายเหตุ`/`สถานะ`/`คิดเป็นร้อยละ` belong to the nearest round to their left, so parsing is positional (`fetchSheetRows` adds `__raw` because `หมายเหตุ` repeats). A legacy `รอบรายงาน` column (one row per round) still works. `kpiResultList(fy, period)` defaults to the latest round, used by the strategy chips and the PDF; Excel lists every round. Quarter rounds: cumulative result meeting the annual target = บรรลุ, else the round forecast of the year-end result decides `คาดว่าบรรลุ` (`KR_LIKELY`) / `เสี่ยงไม่บรรลุ` (`KR_RISK`); result only = `อยู่ระหว่างดำเนินการ`; the year round keeps บรรลุ/ไม่บรรลุ/รอผล; `KPI_Strategy_Code` blank = org-level row). Columns are found by header name; if `ค่าเป้าหมาย`/`หน่วยนับ` are swapped (number in the unit column) they are swapped back. `pct` = result ÷ target, or target ÷ result when `ทิศทาง` says น้อยกว่าดี (no column: name contains "ไม่เกิน"); with no result it uses `ค่าคาดการณ์` (`isForecast`, drawn faded). `status` = the sheet `สถานะ` if filled (บรรลุ/ไม่บรรลุ/รอ…), else result vs target → `บรรลุเป้าหมาย`/`ไม่บรรลุเป้าหมาย`, no result → `รอผล`. Summaries count KPIs per status and never average % across KPIs (different units; user agreed Nov 2026). Org KPIs that are also annual KPIs (e.g. KPI-ST69-03/04/11) are not duplicated as rows: the org row lists them in `ตัวชี้วัดรายปีที่ใช้ผลเดียวกัน`, and `kpiResultFor(code, fy)` resolves those aliases. `renderKpiView(strategies, wantFY)` (called after `ACPDash.start`, and again in `show()` after every header period switch because `show()` rebuilds `#dashboardContent` from `SNAPSHOT`; it opens the period's fiscal year when that year has KPI data) draws cards, per-strategy tables (`kpiResultGroups`) and a year trend for org KPIs when > 1 year exists. `view-strategy` shows `kpiResultChip()` under each org/annual KPI target for `__viewFY`. Org KPI targets on that page and in report topic `strategy` come from `orgTargetText(o, fy)`: the yearly target in `ผลตัวชี้วัดที่สำคัญ` for that fiscal year, falling back to `ตัวชี้วัดองค์กร` (which holds the end-of-plan 2570 targets; user decision Nov 2026, not shown).

- Project risk = **ความเสี่ยงไม่บรรลุเป้าหมาย (สัญญาณเตือนล่วงหน้า / Early Warning)** (user request Nov 2026; renamed late Nov 2026 because the plan book's L × I is assessed by units with a different method, and the roles of กองประเมินผล / กองบริหารความเสี่ยง / กองนโยบายและแผน were still unclear). Steps whose target is "ไม่เกิน N" (e.g. downtime ≤ 6 times/yr, often the heaviest step at ฝทส.) count as 100% while within the ceiling, else N ÷ actual (plan = 1, so forecast = current); they are excluded from Milestone as before.
